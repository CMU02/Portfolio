# 포트폴리오 에디토리얼 디자인 개편

- 작성일: 2026-10-21
- 브랜치 기준: `feat/tiptap-deepdive` (PR #1) 위에서 작업

## 의도

방문자(채용 담당자, 개발자)가 첫 30초 안에 받아야 할 인상은 하나다.

> **"이 사람은 데모가 아니라 실제로 굴러가는 서비스를 끝까지 만들고 운영한다."**

기억에 남아야 할 것은 운영 중인 프로젝트 3개와 각 프로젝트의 핵심 수치 하나다.
(이 방향은 Claude가 레포 내용을 근거로 제안했고 소유자가 "그렇게 해줘"로 채택했다.)

지금 사이트는 섹션을 길게 나열하는 다크 랜딩 페이지라, 프로젝트가 화면 두 개 아래에 있고 카드·글로우·그라데이션·등장 애니메이션이 많다. 직전 작업(PR #1)은 접근성·대비·폰트 수정이라 소유자 눈에는 "디자인이 아예 바뀌지 않은" 상태다. 이번 개편은 눈에 보이는 변화가 목적이다.

## 소유자가 정한 것

1. **스타일: B. 에디토리얼.** 비주얼 컴패니언에서 세 시안(A 운영 콘솔, B 에디토리얼, C 벤토 그리드) 중 B를 선택. 시안 원본: `.superpowers/brainstorm/27000-1792581453/content/home-direction.html`.
   - 밝은 종이 톤 배경, 검은 글자, 큰 타이포, 프로젝트를 표처럼 한 줄씩 나열하고 줄 오른쪽에 큰 숫자 하나.
2. **다크 모드 유지.** 사용자가 전환할 수 있어야 한다.
3. **첫 화면에 운영 중인 서비스 3개 + 핵심 수치.**

## 목표

- 홈 첫 화면(1440x900, 375x812 모두)에서 스크롤 없이 이름, 한 줄 포지셔닝, 프로젝트 3개 줄과 각 수치가 보인다.
- 사이트 전체(홈, 프로젝트 상세/딥다이브, 자격증, 404, 로딩, 개인정보 페이지)가 같은 에디토리얼 시스템을 쓴다. 홈에서 상세로 넘어가도 같은 사이트처럼 보여야 한다.
- 라이트/다크 두 테마 모두 WCAG AA 대비를 지킨다.
- 상세보기가 느리게 느껴지는 원인(원본 이미지 다운로드)을 해결한다. (아래 "이미지 성능" 참고)

## 비목표

- 콘텐츠(프로젝트 본문, 수치) 재작성. 문구는 기존 데이터에서 가져온다.
- Tiptap 콘텐츠 구조, 로컬 편집기, 라우트 구조 변경.
- CMS/DB 도입, 다국어.

## 안티 목표 (기술적으로 돌아가도 실패)

- 개편 후에도 "별로 안 바뀌었다"고 느껴지는 것. 색만 바꾸고 레이아웃이 그대로면 실패다.
- 카드·그림자·글로우·그라데이션·과한 등장 애니메이션이 돌아오는 것.
- 첫 화면에서 프로젝트가 안 보이는 것.
- 다크 모드에서 대비가 무너지거나, 페이지 로드 시 다른 테마가 잠깐 깜빡이는 것(FOUC).
- 딥다이브 콘텐츠가 사라지거나 잘리는 것.

## 디자인 시스템

### 색 토큰 (Claude의 결정, 구현 시 대비 계산으로 확정)

| 토큰 | 라이트 | 다크 |
|---|---|---|
| background (paper) | `#f6f4ef` | `#0a2342` (기존 브랜드 네이비 유지) |
| foreground (ink) | `#111111` | `#fffdf7` |
| muted-foreground | `#555555` 근처, paper 위 AA 이상 | `#8ba3c4` (기존) |
| rule / border | `#d9d5cc` | `#264a7a` (기존) |
| accent | `#0f766e` 근처 진한 teal, paper 위 4.5:1 이상 | `#2ca58d` 계열, 작은 글자는 기존 `--primary-text` |

- 강조색은 accent 하나만 쓴다. 기존 `tech-*`(pink, yellow, purple 등) 장식 색은 본문에서 쓰지 않는다. 의미가 있는 곳(오류·실패 분기 등)만 `destructive`.
- 기존 shadcn 토큰 이름(`--background`, `--foreground`, `--primary`, `--muted-foreground`, `--border`, `--card` …)은 유지하고 값만 테마별로 바꾼다. 컴포넌트가 토큰을 쓰고 있어서 이 방식이 변경 범위가 가장 작다.

### 타이포그래피

- 폰트는 PR #1에서 적용한 Geist(라틴) + Noto Sans KR(한글)을 유지한다. (Claude의 결정: 새 폰트를 추가하지 않는다.)
- 위계는 크기·굵기·자간으로 만든다. 홈 제목은 시안처럼 매우 크게(데스크톱 약 72~96px, 모바일 약 40px), 굵게, 음수 자간.
- 수치는 큰 숫자 + 작은 라벨 조합.
- 한글 본문 `word-break: keep-all` 유지, 제목은 `text-balance`.

### 레이아웃 원칙

- 카드 대신 **가는 구분선(rule)과 여백**으로 구역을 나눈다.
- 콘텐츠 최대 폭을 한 가지로 통일(약 1100~1200px), 본문 읽기 폭은 65~75자.
- 등장 애니메이션은 없애거나 아주 짧은 페이드 하나로 제한. `prefers-reduced-motion` 존중은 유지.

## 페이지별 설계

### 공통 헤더/푸터

- 헤더: 왼쪽 이름(또는 기존 로고 텍스트), 오른쪽 `Work · About · Contact` + 테마 토글 버튼. 스크롤 시 배경만 살짝, 그림자 없음.
- 푸터: 모든 페이지에 공통으로 둔다(현재는 홈 Contact 섹션 안에만 있고 연도가 2024). 연도는 빌드 시점 기준.

### 홈 (`app/page.tsx`)

순서: Hero → Work → About → Contact.

1. **Hero**: 큰 제목 "Idea to Production, Never Let Go." + 한 줄 "만들고, 배포하고, 운영합니다. 백엔드 · AWS"(문구는 Claude 제안, 소유자 확인 필요). `min-h-screen` 제거. 이름 "최현준"은 헤더나 Hero 위 작은 라벨로.
2. **Work**: 프로젝트 3개를 표처럼 한 줄씩. 각 줄 = 이름, 한 줄 설명, 유형(개인/6인 팀 PL), 오른쪽 큰 수치 하나 + 라벨. 줄 전체가 상세 링크. 수치는 딥다이브 `highlights` 첫 항목 또는 시안의 값:
   - Phantom File: `$5 미만` 월 운영비 (시안에서는 `$5 /월`)
   - SubHub: `97%` 토큰 절감
   - CleanBreath: `87%↓` 쿼리 응답 개선
   - 줄 순서: 시안 순서(Phantom File, SubHub, CleanBreath).
   - 이미지 썸네일은 홈 목록에서 쓰지 않는다(시안 기준). 
3. **About** (Claude 제안, 소유자가 이의 없음): 기존 What I Do(Expertise), Growth 섹션을 하나로 줄인다. 짧은 소개 2~3문장, 기술 목록(텍스트), AWS SAA 자격증(→ `/certifications` 링크), 성장 이야기 2~3줄.
4. **Contact**: 이메일, GitHub 링크. 큰 글자 한 줄 + 링크.

### 프로젝트 목록 (`/projects`)

- 홈 Work와 내용이 같으므로 홈의 `/#work`로 합친다(Claude 제안, 소유자 이의 없음). `/projects`는 같은 목록을 보여주는 간단한 페이지로 남기거나 `/#work`로 리다이렉트한다. SEO와 기존 링크를 고려해 리다이렉트를 권장. 딥다이브의 "프로젝트 목록" 뒤로가기 링크도 맞춰 수정.

### 프로젝트 상세 / 딥다이브 (`features/projects/DeepDivePage.tsx`, `components/deepdive/**`)

- 같은 에디토리얼 톤으로 맞춘다. 구조(헤더, 하이라이트 수치, 왼쪽 목차, 본문, 오른쪽 보조 정보)와 Tiptap 블록 종류는 유지하고 시각 처리만 바꾼다.
- `HighlightCards`: 카드 대신 큰 숫자 + 라벨을 구분선으로 나열(홈 Work 수치와 같은 스타일).
- 블록(비교, 의사결정, 지표, 한계점, 코드, 갤러리 등): 박스 테두리·배경 틴트를 줄이고 구분선과 여백 위주로. 코드 블록은 배경이 있어야 읽히므로 유지.
- 목차/사이드바: 텍스트 링크 + 현재 위치 표시(accent), 카드 배경 없음.

### 기타 페이지

- `/certifications`, `not-found`, `loading`, `/projects/subhub/privacy`: 같은 토큰과 타이포로 맞춘다. 개인정보 페이지에 남아 있는 팔레트 색(green/blue/yellow-400)을 토큰으로 교체.

## 테마 전환 (Claude의 결정)

- 기본값은 OS 설정(`prefers-color-scheme`), 헤더 토글로 바꾸면 `localStorage`에 기억.
- `<html>`의 `dark` 클래스로 전환. 지금은 `layout.tsx`가 `className="dark"`를 고정하고 `app/page.tsx`의 `<main className="dark">` 등도 있으므로 이 고정값을 모두 제거한다.
- 첫 페인트 전에 테마를 정하는 작은 인라인 스크립트를 `<head>`에 넣어 깜빡임을 막는다. 라이브러리(next-themes)는 쓰지 않는다: 몇 줄이면 되고 의존성이 늘어난다.
- 토글 버튼: 아이콘 버튼, `aria-label`, 44px 터치 영역.
- mermaid 다이어그램, HyperFrames 영상 등 테마 영향을 받는 요소는 두 테마에서 확인한다.

## 이미지 성능 (상세보기가 느린 원인)

측정 결과(프로덕션 빌드, 2026-10-21):
- 상세 페이지 전환 자체는 50~150ms로 빠르다.
- 원인은 이미지다. CleanBreath 상세로 이동하면 이미지 13.5MB를 받는다(장당 1.7~3.5MB 원본 PNG). `/projects` 카드 썸네일 하나도 1.5MB.
- `lib/image-loader.ts`가 CloudFront URL에 `?width=`를 붙이지만 CloudFront는 무시한다. 과거(커밋 f1fb021) `/_next/image` 사용 시 다수 이미지 동시 로드에서 400 에러가 나서 이 로더로 우회했다.
- 홈에서 스크롤한 상태로 상세로 이동하면, 페이지 아래쪽 갤러리 lazy 이미지까지 한꺼번에 로드가 시작된다.

**소유자 결정: 리사이즈본을 미리 만들어 S3에 올린다.** 호스팅은 Vercel이다. Vercel 이미지 최적화 한도와 과거 400 에러 때문에 `/_next/image`로 돌아가지 않는다.

- 레포에서 참조하는 모든 CloudFront 이미지 키(`data/**`, `content/deepdive/**.json`, 컴포넌트)를 모아, 로컬에서 너비별 WebP 변형을 만든다. 너비: 640, 1280, 1920 (Claude의 결정; 원본보다 큰 너비는 만들지 않는다).
- 이름 규칙(파일 이름 계약): 원본 `dir/name.png` → `dir/name.w640.webp`, `dir/name.w1280.webp`, `dir/name.w1920.webp`. 원본은 지우지 않는다.
- `lib/image-loader.ts`: 요청 너비 이상인 가장 작은 변형 키를 반환한다(없으면 가장 큰 변형). `?width=` 쿼리는 버린다.
- 생성 스크립트는 레포에 두고(예: `scripts/resize-images.ts` 또는 `.mjs`), 새 이미지를 추가할 때 다시 돌린다. 이미 변형이 있는 키는 건너뛴다.
- 변형 누락 검사: 레포가 참조하는 모든 키의 변형이 CloudFront에 있는지 HEAD로 확인하는 스크립트(또는 같은 스크립트의 `--check` 모드). 변형이 없으면 이미지가 깨지므로 배포 전에 돌린다.
- S3 업로드는 외부 쓰기라 실행 시점에 소유자 확인을 받는다. 버킷 이름은 CloudFront 배포(`d2jxs31fe0rfi3.cloudfront.net`)의 오리진에서 확인한다. Phantom File 영상 3개(PR #1)도 같은 업로드에서 함께 올린다.
- 갤러리 썸네일은 `sizes`를 되살려 640 변형을 받게 한다. 라이트박스는 1280/1920 변형.
- 아키텍처 이미지 등 기존 `unoptimized` 우회는 로더가 제대로 동작하면 제거한다.

## 제약

- Next.js 16 App Router, React 19, Tailwind v4, shadcn/ui(Radix), bun. 공개 페이지는 서버 컴포넌트 우선(PR #1에서 정리한 구조 유지).
- 접근성: 대비 AA, 포커스 표시, 44px 터치 영역, reduced-motion, 제목 계층(h1 하나).
- 375px에서 가로 스크롤 없음.
- 빌드(`bunx next build`)와 `tsc --noEmit` 통과. ESLint는 기존부터 실행 불가(범위 밖).
